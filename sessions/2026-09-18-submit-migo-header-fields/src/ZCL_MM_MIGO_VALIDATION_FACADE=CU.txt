CLASS zcl_mm_migo_validation_facade DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC .

  PUBLIC SECTION.
*   Facade that orchestrates the shared validation classes ported
*   from MB_MIGO_BADI, so a single call runs every rule ported so
*   far. Currently wraps:
*     - ZCL_MM_GOODSMVT_VALIDATIONS   (dates, duplicate invoice,
*       GSTIN, STO/rail rules, reservation approval, AFR manifest)
*     - ZCL_MM_DELNOTE_VALIDATIONS    (delivery-note-mandatory
*       Rules A & B, reservation date, WEBRE/GR-based-IV, QM
*       inspection)
*     - ZCL_MM_PACKMATRIX_VALIDATIONS (Cement SILO / packing
*       matrix check)
*     - ZCL_MM_BATCH_GRN_VALIDATIONS  (batch-vs-delivery-note
*       consistency for semi-finished-goods GRs, ported from
*       ZCL_IM_MM_SEND_MAIL's CHECK_HEADER "Block A" - exposed as
*       VALIDATE_ITEMS since the check is genuinely item-scoped)
*
*   NOT yet wrapped, per explicit instruction to defer them:
*   Gate Entry validations (blocked on the GE_NO/GEYEAR input
*   source decision) and any remaining out-of-scope rules.
*
*   IS_HEADER / IT_ITEM is the union of the fields each wrapped
*   class needs, in the same shared shape those classes already
*   read (see each class's own header comment for the mapping
*   notes carried over from MB_MIGO_BADI - in particular,
*   ACTION/REFDOC replace MIGO's dynamic ASSIGN to GODYNPRO and
*   must be supplied by the caller as the caller's equivalent
*   classification). Wiring this facade into
*   CL_API_MATERIAL_DOCUME_DPC_EXT's CREATE_DOCUMENT still requires
*   mapping these fields from the live API_MATERIAL_DOCUMENT
*   deep-entity payload, and inserting the hook call itself - both
*   are separate, still-pending steps.

*    TYPES:
*      BEGIN OF ty_header,
*        budat      TYPE budat,
*        bldat      TYPE bldat,
*        lifnr      TYPE lifnr,
*        lfsnr      TYPE lfsnr,
*        xblnr      TYPE xblnr1,
*        bukrs      TYPE bukrs,
*        bwart_dflt TYPE bwart,
*        action     TYPE godynpro-action,
*        refdoc     TYPE godynpro-refdoc,
*      END OF ty_header .

    TYPES: bwart_dflt TYPE bwart,           "Header-default movement type (MIGO: GODEFAULT_TV-BWART); caller supplies the equivalent, e.g. the movement type of the items being posted
        action     TYPE godynpro-action, "MIGO transaction-variant equivalent, e.g. 'A01', 'A07' - caller-supplied
        refdoc     TYPE godynpro-refdoc. "MIGO reference-type equivalent, e.g. 'R01', 'R05', 'R09' - caller-supplied
    TYPES:   END OF ty_header .
